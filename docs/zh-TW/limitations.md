# 已知限制

這份文件整理了 ChunkLand 目前在實機環境中確認的各項運行特性與邊界限制。我們將每個項目細分為「可觀察現象」、「實際影響」與「建議替代做法」，讓服主與玩家在規劃防護時有最透明的依據。

## 一、點火按人判定，爆炸走爆炸規則

**可觀察現象**：在領地內「把火點起來」按人判定、預設拒絕：地主與被明確授權（信任或領地預設放行點火）的人點得著，陌生人點不著。無主點火——岩漿、閃電、裝了打火石的發射器、生物射出的投射物——改走火焰蔓延規則裁決，內建就是拒絕，所以預設擋得下；要開放的話，地主可逐領地調整該規則。

**實際影響**：陌生人不能在領地內放火；無主火源預設起不來。爆炸另算：炸壞方塊與炸傷生物走地形爆炸與實體爆炸規則，不走點火權限——爆炸規則放行的領地照樣會被炸壞，即使點火對所有人都拒絕。

**建議替代做法**：想讓特定成員能點火，用信任或領地預設放行點火動作；想擋爆炸，調的是爆炸規則而不是點火。

> 驗證層級：程式層級確認。

## 二、領地環境規則可逐領地調整，跨界維持攔阻

以下 11 項環境機制地主可用 `/land rule` 逐領地調整（三態 `ALLOW`、`DENY`、`INHERIT`；`INHERIT` 刪掉覆寫，退回世界、全域與內建層）：

PVP、地形爆炸、實體爆炸、火焰蔓延、火焰燒毀、生物破壞、水流、活塞、漏斗傳輸、敵對生物生成、被動生物生成。

世界與全域層走 `config.yml` 的 `rule-defaults`；管理介面的規則頁並排顯示明確值、有效值與來源層。規則對地主沒有豁免：設成拒絕時地主自己也會被擋。

**實際影響**：想在特定領地開 PVP 競技場、用 TNT 開礦，現在地主自己就能開。但活塞、液體、漏斗只要跨越領地邊界（從外面進來、從裡面出去、或跨兩塊不同領地，包含同一位地主相鄰的兩塊領地之間）一律攔截——這一點不屬於任何規則，也無法開放。

**建議替代做法**：把整套機器蓋在同一塊領地內，避開跨越領地邊界的活塞、流體與漏斗裝置。

> 驗證層級：程式層級確認。

## 三、管理介面僅列出線上玩家

**可觀察現象**：Java 版的 `/land manage` 箱子管理介面可正常運作（支援切換權限與確認、檢視名單、翻頁），但在成員名單與黑名單分頁中，**「新增」選項僅列出當前在線的玩家**。

**建議替代做法**：若要將離線好友加入信任，請直接使用聊天指令 `/land trust <玩家ID>`；解除離線玩家封鎖請使用 `/land unban <玩家ID>`。

小提醒：輸入玩家 ID 時，該玩家必須**至少登入過伺服器一次**，外掛才能解析其帳號資料；從未登入過的名字是找不到的。若使用 UUID 則無此限制。

> 驗證層級：實機確認（Folia 26.2）。

## 四、進入（ENTRY）的現行語意

**可觀察現象**

| 面向 | 當前運行狀態 |
| --- | --- |
| 進入預設值 | 預設為**放行**（`subject-defaults.global.ENTRY: ALLOW`），未被封鎖的訪客可自由走入已載入的領地 |
| `/land ban` 效力 | 黑名單依然有效，且優先權高於世界與全域預設，能確實攔阻被封鎖者 |
| 阻擋退回路徑 | 玩家會被平順退回邊界外約 3 格；空間不足時逐步縮短；完全無安全落點則退回原位或取消移動 |
| 退回落點範圍 | 僅選取已載入且區域相符的區塊，絕不為了找退回點額外載入新區塊 |
| 封鎖生效時效 | 被 ban 的玩家若已在領地內，**不會被瞬間傳送離開**，而是等他下一次移動時推回邊界外約 3 格 |
| 推回冷卻時間 | 預設 500 毫秒，可透過 `feedback.push-out-cooldown-millis` 調整 |
| 判定範圍 | 僅檢測該次移動的起點與終點，**不逐格檢測路徑** |
| `/tp` 傳送 | 不受攔阻，詳見[第十節](#十tp-傳送不受進入entry攔阻) |

**實際影響**：封鎖並非瞬間傳送離場，對方若原地不動會暫留領地內，直到下次移動才被推回；連續嘗試闖入時，推回之間有短暫冷卻。

**建議替代做法**：若對方在被 ban 後仍停留領地內，可請其自行離開或洽管理員協助；地主亦可將進入預設改為拒絕（連帶阻擋路人），修改方式請見[伺服器管理指南](server-guide.md#陌生人進入預設放行還是關閉)。

> 驗證層級：實機確認（Folia 26.2）。

## 五、圈選與子領地的現況差異

### 圈選：維持矩形調整，暫無逐塊增減

「編輯選區時左鍵加一塊、右鍵減一塊」的功能尚未推出。目前左鍵與右鍵操作效果相同，皆為矩形調整：固定第一角、更新第二角。

**建議替代做法**：藉由重新點選對角調整矩形大小，使其涵蓋目標範圍。

### 子領地：深度延伸後請再次確認

子領地執行深度延伸（`extend`）後，即時索引刷新可能存在短暫時序差。系統透過確認集合機制保障安全：延伸成功後，提示會請你重新執行一次建立或更新確認。

**建議替代做法**：看到「已延伸，請重新執行建立／更新確認」時，直接重新點擊或輸入一次確認指令即可，不需重新劃定選區。

> 驗證層級：實機確認（Folia 26.2）。

## 六、ActionBar 阻擋提示語言

**可觀察現象**：動作攔阻提示（ActionBar）統一以**伺服器預設語系**渲染，而非客戶端自訂語系。

**實際影響**：僅為顯示語言差異，底層保護判定完全不受影響。

> 驗證層級：實機確認（Folia 26.2）。

## 七、原子授權與記憶體來源

這項機制涉及進階的架構一致性保證：

**可觀察現象**：寫入領地預設值時，系統會在同一筆交易內校驗送出前的「授權世代」是否與資料庫一致；若不一致則安全拒絕整筆變更。僅有資料庫來源的異動（信任、解除信任、綁定、群組設定）會推進世代。

設定檔預設值、管理員豁免與伺服器領地協管這三項屬於**記憶體來源**，不推進世代，亦不參與交易內比對；其權限撤銷僅在進入資料庫寫入前的閘門檢驗時被捕捉。

**實際影響**：在極度忙碌或排隊延遲的情況下，若閘門通過後才撤銷記憶體來源的授權，該筆已排隊的在途寫入仍會成功。

**建議替代做法**：撤銷記憶體權限後，建議稍候當前操作完成，再透過 `/land inspect` 確認現況設定符合預期。

> 驗證層級：程式層級確認。

## 八、設定檔損毀時的自動保護

**可觀察現象**：ChunkLand 開服時會嚴格驗證設定檔。若檔案損毀或遺失，外掛會自動啟用上次確認可用的備份（`config-last-known-good.yml`），或啟動極端保守模式（全服停止圈地、收緊保護、預設阻擋），**絕不會靜默重設為內建預設**。

詳細的修復步驟請參考[伺服器管理指南](server-guide.md#設定檔損壞或遺失時的自動修復)。

> 驗證層級：程式層級確認。

## 九、高速移動可能穿過極薄的子領地

**可觀察現象**：移動檢測僅校驗該遊戲刻移動的「起點」與「終點」，不追蹤途中經過的每一格。

若某個子領地厚度非常單薄（例如只有 1 格寬），而玩家使用鞘翅、煙火、冰上船、三叉戟或高空自由落體，在單一遊戲刻內直接跨越該子領地（起點與終點皆在子領地外），該次移動將不會觸發進入推回。

**實際影響**：高速穿越僅代表玩家「飛過去」，不會滯留在子領地內；穿越後所到之處的破壞、開箱與互動依然會根據當下方塊位置嚴格判定，玩家絕不會因高速穿越而獲得任何操作權限。

**建議替代做法**：若將子領地作為重要防線，請適度增加厚度（垂直方向建議 ≥ 4 格以阻擋自由落體，水平方向建議 ≥ 8 格以防範滑翔）；或改用母領地層級的封鎖來徹底防護。

> 驗證層級：程式層級確認。

## 十、`/tp` 傳送不受進入（ENTRY）攔阻

**可觀察現象**：當管理團隊或主控台使用 `/tp` 將玩家直接傳送進領地時，進入判定不會攔阻該次傳送。落地後玩家可正常走動或自行離開，系統不會主動將其推離。

**實際影響**：管理端指令 `/tp` 具備繞過門禁的能力；一般玩家的常規步行進入依然會被確實阻擋。

**建議替代做法**：若要處置特定闖入對象，可使用 `/land ban`（對方在下次移動時會被自動推離邊界），並謹慎控管伺服器的傳送權限。

> 驗證層級：實機確認（Folia 26.2）。

## 十一、`/land inspect` 與公開讀取 API 的版本號可能不同步

`/land inspect` 顯示的結構版本號與策略版本號，來自該次呼叫當下讀到的不可變快照；公開讀取 API 每次呼叫同樣讀自己當下的一份快照。兩邊若在一次寫入前後各讀一次，看到的版本號就會不一樣——沒有哪一份比較正確，每一份都是它呼叫當下的真相。

> 驗證層級：程式層級確認。
