# 伺服器管理指南

這份指南協助服主完成 ChunkLand 的部署調優、權限配置，並介紹設定檔損毀時的自動修復與安全備援機制。各項語法細節可隨時查閱[指令參考](reference/commands.md)、[設定參考](reference/configuration.md)與[權限參考](reference/permissions.md)。

## 環境需求

| 項目 | 版本 | 必須性 |
| --- | --- | --- |
| 伺服器核心 | Folia 26.2 | 必備。僅支援 Folia 多執行緒架構 |
| Java 執行環境 | Java 25 | 必備 |
| 基礎前置外掛 | AceLib 1.3.0 | 必備。缺少則外掛無法啟動 |
| Vault 系經濟外掛 | 任意相容版本 | 選配。只有把 `economy.enabled` 改成 `true`（預設為 `false`，圈地免費）時才需要，用於圈地計價與退款 |
| LuckPerms | 任意相容版本 | 選配。提供玩家額度中繼資料支援 |
| CoreProtect | 任意相容版本 | 選配。提供 `/land history` 方塊查詢 |

外掛描述檔與編譯設定中標記的 `26.1.2` 僅為相依標記。**ChunkLand 深度依賴 Folia 的非同步區塊調度，無法在標準 Paper 上運行**，請勿將其安裝於 Paper 伺服器。

## 從原始碼建置

專案目前處於開發階段，尚未在 Maven 或 GitHub 發布預編譯 Release，請直接從原始碼建置 jar 檔：

```bash
./scripts/build-acelib.sh          # 下載並校驗編譯所需的 AceLib 1.3.0
./gradlew build --no-daemon --console=plain
```

建置產物位於 `chunkland-plugin/build/libs/chunkland-plugin-0.1.0.jar`。此檔案已內嵌核心相依（API 模組、SQLite 驅動、SnakeYAML），伺服器的 `plugins/` 目錄不需要額外補充執行庫。

本專案工具鏈鎖定 Java 25；`./gradlew build` 會自動執行完整的單元測試與架構邊界檢查，執行時間會比純編譯稍長。

## 安裝步驟

1. 將 AceLib 1.3.0 放進伺服器的 `plugins/` 目錄（ChunkLand 在 `plugin.yml` 宣告了 `depend: [AceLib]`，缺少前置時伺服器會拒絕載入）。
2. 將編譯出的 `chunkland-plugin-0.1.0.jar` 複製到 `plugins/`。
3. 啟動伺服器。

初次啟動完成後，外掛會在 `plugins/ChunkLand/` 目錄下自動建立以下檔案：

| 路徑 | 內容與用途 |
| --- | --- |
| `config.yml` | 主設定檔，每次開服時由此載入參數 |
| `config-last-known-good.yml` | 上一次成功驗證且載入的設定備份（容錯備援用） |
| `lang/en_US.yml`、`lang/zh_TW.yml` | 預設語言檔 |
| `chunkland.db` | 儲存所有領地與審計數據的 SQLite 資料庫 |

更新外掛 jar 檔後請完整重啟伺服器。換下來的舊 jar 檔請移出 `plugins/` 目錄，避免保留在同目錄下造成干擾。

## 設定變更與重啟原則

**Folia 環境不支援熱重載**：ChunkLand 沒有提供 `/chunkland reload`，Bukkit 傳統的 `/reload` 在 Folia 架構下亦可能破壞區塊與多執行緒狀態。因此每次修改 `config.yml` 之後，請安心重啟伺服器以套用變更。

若擔心設定手滑改錯，可參考下一節關於設定檔自動備援與修復的設計。

## 陌生人進入預設：放行還是關閉？

預設設定檔中配置如下：

```yaml
subject-defaults:
  global:
    ENTRY: ALLOW
```

這意味著**未受信任的陌生訪客預設可以走進已載入的領地**。地主個人的 `/land ban` 依然有效——黑名單在權限層具有最高優先權，能確實阻擋特定玩家。

若你的伺服器風格希望領地預設對外封閉，請將設定改為拒絕：

```yaml
subject-defaults:
  global:
    ENTRY: DENY
```

你也可以為特定世界單獨設定，例如 `subject-defaults.worlds.<世界名稱>.ENTRY`（注意：世界名稱大小寫敏感）。

### 進入被阻擋時的退回機制

| 情況 | 系統應對行為 |
| --- | --- |
| 一般玩家步行闖入被拒 | 在玩家周圍繪製紅色邊界粒子，並平順退回邊界外約 3 格 |
| 邊界外退回空間不足 | 自動逐步縮短退後距離，尋找安全落點 |
| 完全找不到安全落點 | 退回移動前的位置；若仍不安全則取消該次移動 |
| 已被 ban 的玩家恰好站在領地內 | 不會瞬間強制傳送，而是等他下一次移動時推回（優先推往最近的驗證出口） |

退回尋找落點時，ChunkLand 僅使用當前已載入且區域相符的區塊，絕不會為了找退回點而額外載入新區塊。

重要運行特性：

- 推回之間設有冷卻時間（預設 500 毫秒），可透過 `feedback.push-out-cooldown-millis` 調整。
- 移動進入判定採用起點與終點檢測，**不逐格檢測路徑**；高速移動（如鞘翅或冰船）可能越過單薄的子領地。
- 管理員透過 `/tp` 傳送進入**不會**被攔阻。

更詳盡的行為說明請參考[已知限制](limitations.md)。

## 設定檔損壞或遺失時的自動修復

每次開服時，ChunkLand 會嚴謹檢驗設定來源，並根據狀態自動選擇最安全的方案：

### 四種載入情境

| 情境 | 採用的設定來源 |
| --- | --- |
| `config.yml` 格式正常 | 正常讀取你的 `config.yml`，並同步更新備份檔 |
| `config.yml` 語法錯誤或驗證失敗（損毀） | 自動啟用上次確認可用的備份（`config-last-known-good.yml`）；無備份時啟用保守模式 |
| 設定檔不存在且從未使用過（全新開箱） | 自動釋出內建預設的 `config.yml` 並以此啟動 |
| 設定檔遭誤刪，但過去曾成功運作過 | 自動從備份檔恢復；無備份時啟用保守模式 |

特別注意：**設定檔損毀時絕不會靜默重設為內建預設**，避免因語法疏忽而意外放寬全服的領地保護。

### 保守模式（Fail-Closed Safe Mode）

當設定損毀且連備份檔都不存在時，外掛會進入極端保守模式：

| 項目 | 保守模式行為 |
| --- | --- |
| 新增宣稱 | 全世界停用圈地功能 |
| 經濟系統操作 | 停用，圈地計價不可用 |
| 保護邊界 | 從嚴判斷 |
| 權限判定底線 | 一律以拒絕（DENY）為基準 |

這是刻意的安全設計：寧可在設定出錯時暫時收緊功能，也絕不讓伺服器暴露在無防護風險中。

### 主控台日誌識別

| 狀態 | 日誌等級 | 訊息重點 |
| --- | --- | --- |
| 全新安裝開服 | `INFO` | 提示產生檔案的絕對路徑，並提醒後續編輯需重啟 |
| 設定損毀或檔案遺失 | `ERROR` | 印出設定檔路徑與實際採用的後備來源，精確指出失敗的 YAML 鍵路徑（如 `worlds.world.vertical-mode`） |
| 全新安裝但檔案無寫入權限 | `WARNING` | 提示檔案無法落地，外掛暫時以記憶體預設值運作 |

### 損壞修復三步驟

1. 關閉伺服器。
2. 開啟 `plugins/ChunkLand/config.yml`，根據主控台提示修正語法錯誤（外掛絕不會擅自覆寫或刪除你的原始檔案）。
3. 重新啟動伺服器。

修復成功後，外掛會重新讀取你的 `config.yml` 並自動更新 `config-last-known-good.yml`。

> **維運備註**：本節設定備援機制已通過完整的自動化單元與整合測試驗證。若在實際營運中遇到設定檔讀取異常，請優先查閱伺服器主控台輸出的 ERROR 紀錄以定位問題欄位。

## 資料庫維護與安全備份

所有領地、成員名單、群組與審計數據皆統一儲存於 `plugins/ChunkLand/chunkland.db`（SQLite 格式）。

**千萬不要在伺服器運轉中直接複製資料庫檔案！** SQLite 在運行期間會對資料庫加鎖，直接複製極易導致備份檔損毀。最安全的方式是先關閉伺服器再進行備份。

關閉伺服器後，備份整個 `plugins/ChunkLand/` 目錄：
- 若目錄中留有 `chunkland.db-wal`（寫入預寫日誌）或 `chunkland.db-shm`（共享記憶體），代表停服時有尚未完全回寫主檔的資料，**務必將它們與主資料庫一併複製**。
- `config.yml` 與語言檔也建議一同備份，保障自訂文案與設定參數安全。

同理，若伺服器有安裝 LuckPerms 或 CoreProtect，其資料庫檔在運轉期間也切勿強行複製，建議善用各外掛內建的指令或停機維護時備份。

### 還原方式

還原一樣要先關閉伺服器。把當初備份的整個 `plugins/ChunkLand/` 目錄照原樣放回去：資料庫（`chunkland.db`，以及當時一起複製的 `chunkland.db-wal`／`chunkland.db-shm`）、`config.yml`、`config-last-known-good.yml` 與語言檔，**全部放回之後才啟動伺服器**。

最容易漏的是這兩樣。只把 `chunkland.db` 放回去、卻少了當時一起備份的 `-wal`／`-shm`，可能丟掉尚未併回主檔的資料；只把 `config.yml` 放回去、卻少了 `config-last-known-good.yml`，就失去設定讀不動時的備援——而那正是你最需要它的時候。

絕對不要在運轉中的伺服器上直接覆蓋還原：覆蓋活的 SQLite 檔案跟運轉中複製一樣有損毀風險，正確順序是先停機、換回整個資料夾、再啟動。

## 審計紀錄維護

設定檔中的 `audit.retention-days` 決定審計日誌保留天數（預設 180 天；設定為 `0` 表示永久保存）。

日誌清理會在專屬的持久化執行緒上分批非同步執行，絕不阻塞主執行緒。清理作業**僅針對過期審計日誌**，領地擁有權、區塊邊界與交易帳本數據永遠不會被清理刪除。

查詢審計紀錄可使用 `/land log` 指令，支援依照玩家、時間、操作類型與世界進行分頁篩選。

## 語系配置與客製化文案

預設語言由 `messages.default-locale` 指定（預設 `en_US`，支援 `zh_TW`）。

改文案時請留意**語系鍵的覆蓋邏輯**：外掛更新時若加入了新鍵，會自動從 jar 內建檔案補足；但伺服器磁碟上已存在的自訂文案會維持優先。若想套用最新的內建文案，可手動對照修改磁碟上的 yml 檔。

目前阻擋與拒絕提示（ActionBar）統一採用**伺服器預設語系**渲染；客戶端自訂語言玩家看到的提示依然以伺服器設定為準。

## 選配外掛相依說明

| 外掛 | 缺席時的系統反應 |
| --- | --- |
| Vault 系經濟外掛 | 購買關閉（`economy.enabled: false`，預設）時沒有影響，圈地免費；購買開啟時，玩家圈地會提示經濟服務不可用並安全阻擋 |
| LuckPerms | 額度計算退回設定檔靜態預設值，無法套用權限中繼資料額度 |
| CoreProtect | `/land history` 指令提示功能暫時無法使用；其餘保護功能完全正常運作 |

以上三者皆為軟相依，即使沒有安裝也不會妨礙 ChunkLand 正常開服。

## 開服前檢查清單

正式開放玩家進入前，請依序確認以下項目：

| 檢查項目 | 重點理由 |
| --- | --- |
| 確認 AceLib 1.3.0 在 `plugins/` | 缺少基礎前置外掛，ChunkLand 無法啟動 |
| 確認核心為 Folia 26.2、Java 25 | 確保多執行緒非同步排程完全相容 |
| 確認已發放指令權限節點給玩家 | 所有權限預設為 OP，未發放前一般玩家無法圈地 |
| 評估 `subject-defaults.global.ENTRY` | 預設為 `ALLOW`；若要完全防闖入請改為 `DENY` |
| 評估是否需要調整 `limits` 額度上限 | 根據伺服器經濟體系微調玩家領地與區塊數量 |
| 確認伺服器定時備份包含 `plugins/ChunkLand/` | 保障領地資料庫與設定檔完整性 |

十一項領地環境規則（如 PVP、水流與活塞防護）目前由系統安全預設託管，暫不開放自訂，詳情請參考[已知限制](limitations.md)。
